# 从机传感器与通信约定

## 当前单只 SG90 远程窗口测试（优先于历史单次定位说明）

- 以 `PROTOCOL_V4.md` 的窗口约定为准。实物现已确认为连续旋转型；业务模式默认0，启动PB8/TIM4_CH3的停止脉宽（默认1500 us）并等待主机命令，不自动往返。独立模式1仍保留阻塞往返，不能用于链路联调。
- 业务接口改为300 ms定时动作：关窗1300 us、开窗1700 us，计时到期后在下一次主循环更新停止脉宽，后续PWM周期生效，不重启PWM、不调用阻塞延时。`slave_servo_test.h` 中配置运行时间及停止脉宽；停止点需要空载校准，不能将定时动作解释为确定角度或机械到位。
- 同方向在途重复命令不重新计时、不重复写PWM；反方向新命令覆盖当前动作并重新计时；停止后的新命令可再次运行一段，不保证机械角度不累加。旧自动定位接口和独立测试保留，但不能覆盖业务手动模式；运动启动或自动停止失败均停机并记录诊断，不阻塞通信/传感器。
- 只接受主机2/group1→从机3/group1的窗口11帧及载荷 `[1,0/1]`。先预留独立15字节ACK槽再执行；槽已占用时不执行不同请求，由主机超时处理。相同待确认请求不重复初始化或覆盖回复。ACK沿原flow回主机，成功只证明动作PWM设置，不确认动作完成、自动停止成功或机械到位；至少等待20 ms预加载及50 ms接收静默，有限UART重试。
- ACK优先于遥测发送，但不复用、改写或清除遥测/强制采样及重复缓存；声学/BME过期逻辑仅处理遥测。不得启用另外三路舵机或改变TIM2/TIM4、声学、I2C、LoRa引脚。
- 本次只做一只空载SG90，独立5 V供电并共地。三板及Python上位机须配套更新，用户手动烧录；业务HEX/ELF/map保留明确角色名称，不能拿独立测试符号解读业务RAM。

- 启动顺序保持原业务实现：先完成 LoRa 初始化，再启动声学与舵机。因此复位后停止脉宽并非立即输出，LoRa 配置重试时会延后。业务输出停止脉宽（默认1500 us）并等待窗口命令；仅测试单只空载连续旋转型舵机，不宣称实测绝对角度。若1500 us仍慢转，先断电并校准停止脉宽。

- `Bsp/sg90_test_pwm.*` 仍负责硬件 PWM、脉宽限幅和失败停机。下方单次定位为历史自动模式，当前业务使用手动接口；声学/通信约定仍有效。本次不迁入稳定平台的 IMU、显示、PID 或 TIM3 配置，不新增目录。
- 接线仍为信号 PB8、舵机独立稳压 5 V、舵机电源地与从机 GND 共地；当前只接这一只空载舵机，不装窗户连杆。异常抖动、堵转或发热立即断电。
- 本次在现有 PB8 单通道接入窗口命令，其余三路仅文档预留，不配置额外 GPIO/PWM 通道，不改变 TIM2 参数或 AFIO 重映射。验证包括业务与舵机电脑侧回归、Keil 构建和链接入口检查；真实链路、PB8 波形、电源和机械运动仍由用户上板验收，代理不自动烧录。

- 旧 `LoraSlaveV1_slave_window_business_PB8.hex` 持续输出1300/1700 us，不包含定时停止；旧 `LoraSlaveV1_slave_business_PB8.hex` 属于更早恢复版本。本次原样保留旧副本，定时停止验收使用本次正常构建的默认HEX（或哈希一致的timed300ms留档）。独立测试只在用户明确改为模式1并重新构建时使用，不能拿来做业务链路联调。

## 当前双声学上传约定（优先于下方历史阶段说明）

- 共同协议以 `PROTOCOL_V4.md` 为准。从机现回复26字节：flags=08，BME在1–8，9–17为FF，声音1/2在18/22，各为小端u32，FFFFFFFF表示无效。
- 声音为最近1秒内各通道去直流短窗RMS的最大值，单位PCM计数。32条固定历史，查询不清空；保持任一通道故障共同失效和300 ms新窗口超时，清空旧峰值。
- 待发及重复回复保留源窗口tick和失效代次，发送前校验，过期置无效并按实际载荷长度重算CRC。参数1仅强制BME转换，声学不额外等待。
- PA8→PB13、PB0→PB12跳线和现有捕获资源不变；保留PB8/TIM4_CH3的SG90测试，不改其复位行为。
- 本轮主机、从机、控制室都须由用户配套烧录。复位仅中位等待窗口命令，实板烧录前确保舵机安全。

- `slave_protocol_runtime.*`：v4 拆帧、请求匹配和有界延迟回复；`slave_bme280.*`：采样状态机及 RAM 诊断。硬件驱动在 `Bsp/bme280.*`，I2C1 初始化与恢复在现有 `Core/Src/i2c.c`。不恢复 RTOS，不使用通信串口打印调试文本。
- PB6=SCL、PB7=SDA，硬件 I2C1 100 kHz、开漏、上拉至 3.3 V；CSB 必须为高，SDO 决定 0x76/0x77。仅接受 BME280 ID=0x60，不将没有湿度的 BMP280 视为成功。
- 每秒强制模式 ×1 温湿压、滤波关闭；触发后主循环等待 10 ms 再读取，最多等待 50 ms。HAL I²C 每次操作超时 10 ms；总线恢复包含有界 9 个 SCL 脉冲和 ST ES096 模拟滤波器 BUSY 恢复序列，失败每秒重试。初始化失败不进入 Error_Handler 死循环。
- `SlaveBme280Diag` 保存地址、ID、错误、校准状态、采样计数和更新时间。失败立即失效，样本满 2 秒无效；重新接入自动恢复。
- 从机遥测仅回答本组主机的 v4 0x01 请求，参数 0 读缓存，1 等待一次新 BME 测量（失败也结束并回复无效值）；窗口 0x11 的独立 ACK 见顶部约定。遥测回复 source=3/group=1、destination=2/group=1，流水号原样回显，26 字节数据区：flags=08，温湿压在1–8，9–17全FF，声音在18–25。主机聚合时将从机1–8放到上行9–16，不覆盖主机BME。
- 从机不主动广播；回复前至少静默 50 ms，转换等待不阻塞接收；重复请求缓存最多 2 秒且区分参数。声学采样独立运行，雨滴仍未实现。
- 排队或重复发送时再次检查样本更新时间；发送前已失效/过期的快照改成占位值并重新计算 CRC，不能靠重复请求延长数据寿命。
- 验证：主从分别 Keil 构建；电脑侧测试放 `tests/`，不加入固件。交付 HEX 由用户烧录，再检查 ACK、ID、校准、连续采样、断开恢复和五分钟真实链路运行。
- 本目录只放业务源码、头文件及约定；不放 HEX、串口日志、临时下载或测试产物。

## 本轮交付与实板验收

- 主机、从机、控制室最新HEX分别由各自 `MDK-ARM/LoraSlaveV1.0.uvprojx` 构建；按共同协议末尾交付约定使用明确角色名的窗口业务HEX。控制室实际工程位于 `控制室/控制室/`。由用户烧录三块板，不要误用另一个目录的同名 `LoraSlaveV1.hex`。
- 上位机运行更新后的 `通风改/上位机/main.py`；旧打包 EXE 未在本轮更新，不用旧界面验收窗口控制或双 BME。
- 空载验收：复位以停止脉宽等待；开窗1700 us、关窗1300 us，各运行300 ms后回停止脉宽；在途重复同动作不能延长计时。ACK成功只确认动作PWM设置。窗口超时/从机断电显示结果未知，恢复后不自动补发窗口命令；窗口操作前后检查遥测继续正常刷新。定时动作不是固定角度；停止后若仍慢转，须校准停止点，不应延长运行时间来掩盖。
- 供电后检查 `SlaveBme280Diag`：`chip_id=0x60`、`address_7bit=0x76/0x77`、`calibration_valid=1`、`sample_success_count` 连续增长。异常查看 `last_error`（HAL 状态 0–3，4=量程）和 `i2c_error`。
- 检查 `SlaveRuntimeDiag.request_count/reply_count`、`MasterRuntimeDiag.slave_response_match_count`；上位机应显示六项BME、两路声音和从机链路。flags=0F但某传感器为 `--` 表示无线应答正常、对应数据无效；flags=0B表示没有匹配到从机应答。旧18字节的flags=7/3仍兼容，但声音为 `--`。
- 断开从机电源：主机三项继续显示，从机离线；恢复电源后自动恢复。断开从机 BME：链路仍在线，但从机三项无效；重新接入后自动重试恢复。
- 连续运行至少五分钟，人工操作风机1/PB1、风机2/PB8，检查ACK、六项BME、左右声音和主机PB13既有灯带功能。电脑侧虚拟五分钟测试不能替代此项。
- BME 的实板验收仍按以上项目执行；用户已确认开始声学采样阶段，不能将声学软件测试当成 BME 或声学的实板验收。

## SG90 单只空载定位测试（历史自动模式，业务已改手动）

- 本阶段只启用 PB8/TIM4_CH3，一只 SG90 不装连杆；PA8/PB14/PB9 不增加舵机输出。当前 TIM1_CH1 已用于声学 BCLK，TIM1 的周期不能同时供 PB14 输出 50 Hz，禁止覆盖声学 TIM1/TIM3。
- `Bsp/sg90_test_pwm.*` 只负责 TIM4_CH3 的启动、脉宽更新和失败停机；`App/slave_servo_test.*` 负责非阻塞、单次定位序列和 RAM 诊断。TIM4 初始化保持在 `Core/Src/tim.c`，并同步 `.ioc`；不新增目录，不把测试代码加入通信协议。
- TIM4从无业务读取的旧10 ms计数时基改为PSC=71、ARR=19999（72 MHz下50 Hz、1 us分辨率），不启动更新中断，只启CH3。PB6/PB7 I2C1、声学时钟、LoRa串口及BME字段保持原样；遥测扩展遵循共同协议，不得将I2C1重映射到PB8/PB9。
- 每次复位自动执行一次 1500 -> 1300 -> 1500 -> 1700 -> 1500 us，每个目标停留约 2 秒；每次主循环调用最多推进 10 us，每次推进至少间隔 20 ms，长阻塞后不追赶跳步。完成后持续输出 1500 us，不自动重复。该诊断仅记录输出脉宽，不表示舵机实际到位，也不把脉宽声明为绝对角度。
- 首帧从零脉宽启动，再通过 CCR preload 在完整周期边界送出 1500 us；后续只更新 CCR，不复位计数器或生成额外 UG。启动前配置校验、启动或脉宽更新失败记录诊断并将 PB8 拉低，不重试或阻塞传感器/通信。
- 接线：SG90 信号接 PB8，电源接独立稳压 5 V，电源 GND 与从机 GND 共地；只接一只，舵盘空载，运行中不要拨动或顶住输出轴。出现持续抖动、堵转或发热立即断开舵机电源。复位会重新执行测试，保持中位仍需供电。
- 验证：从机 Keil 构建；`tests/test_slave_servo_test.c` 用假 PWM 驱动检查单次序列、限速、停留、时间回绕、长停顿及失败停机；不能替代示波器检查 PB8 的 20 ms 周期/1300–1700 us 高脉冲或实物定位。HEX 仅由用户烧录。

## 双 SPH0645 声学采样与上传

- `Bsp/sph0645.*` 独占TIM1_CH1、TIM3_CH3、SPI2和DMA1 Channel4；`acoustic_processing.*` 为无HAL依赖的PCM/RMS算法；`slave_acoustic.*` 为主循环采样、暖机、1秒历史统计和RAM诊断。不得修改TIM2/TIM4（TIM4_CH3已由SG90测试占用）、BME I2C1或LoRa串口；声音按共同协议的26字节遥测上传。
- 两个 SPH0645LM4H-B 共用 3.3 V/GND、PB13/BCLK、PB12/WS、PB15/DATA；一个 SELECT 接 GND（左），另一个接 3.3 V（右）。新增跳线 PA8→PB13、PB0→PB12。PA8/PB0 是推挽时钟输出，PB12/PB13 是输入，PB15 为下拉输入；PB12 不作为 SPI 硬件 NSS，也不作为输出。
- STM32F103C8 没有硬件 I²S。72 MHz 下 TIM1 PWM2 分频 35 产生约 2.057143 MHz BCLK，TIM1 UPDATE 经 TIM3 ITR0 外部时钟模式 1 再分频 64 产生约 32.142857 kHz WS。SPI2 从机、16 位、MSB first、CPOL=0/CPHA=1，在下降沿采 DATA；TIM3 WS 在该下降沿后改变。初始化 UG 必须在联动和接收启动前完成。
- 先启动接收 DMA 与 TIM3，最后启动 TIM1；每槽两次 16 位接收、每帧左/右共四个半字。首个完整稳态槽的 MSB 位于合并 32 位数据 bit31，取 bit31–14 并做 18 位符号扩展；bit13–8 应为零，末八位高阻尾部不参与校验。首 100 ms 丢弃；实板需核查时钟、原始半字、零填充和左右对应，不能仅凭 DMA 增长声称麦克风正常。
- DMA 循环缓存 8192 字节，两半各 512 个立体声帧；中断只发布完成信息。主循环复制到独立 4096 字节快照，并在复制前后核查 DMA 写入半区、序号和挂起标志。发现覆盖丢弃整块，不能计算混合新旧数据；丢块后重新累计 RMS 窗口。DMA 错误、SPI overrun、双边界中断积压或 100 ms 无完整块停采并每秒有界重试，不阻塞无线服务。
- 每 2048 个连续立体声样本约 63.7 ms，分别去直流计算整数 RMS；单位为 18 位 PCM 计数，不是校准后的 dB，也不是虫害识别。静音/零值合法但不能证明模块在线；非零计数、峰值、均值和零填充错误分别诊断。超过 300 ms 未得到窗口即失效。
- `Sph0645Diag` 查看捕获、错误和丢块；`SlaveAcousticDiag` 查看两路 RMS、原始半字、零填充错误及窗口状态。断点暂停时冻结 TIM1/TIM3；长暂停可能使麦克风重新暖机，复位后再验收。禁止在采样中断打印、等待或计算 RMS。

## 当前四路360°连续旋转舵机约定

- 遵循 `../PROTOCOL_V4.md` 的 `SET_WINDOW=0x11`，载荷 `[servo_id,0/1]`，编号1..4对应从机PB8/PB9/PB10/PB11。React界面显示四路独立开/关按钮和各路命令状态；Tkinter回退使用编号选择及对应状态。待发及待确认事务保存编号，ACK仅更新对应路。保留用户已有粮仓视图及模拟温度改动，不新增角度输入、数据库字段或依赖。
- 未连接时禁用按钮；前序遥测/风机未结束时只暂存一次窗口动作，并暂停新增遥测/风机发送。窗口待发或待确认期间禁用两个按钮；从实际串口发送起等待8秒，只匹配原流水号、命令11及合法状态0–3的ACK。
- 实物为360°连续旋转型，不做角度定位；开窗1700 us、关窗1300 us各运行300 ms，然后从机设置1500 us停止脉宽。1500 us需先空载校准，不能假定实际已经停止。
- 成功ACK只确认动作启动PWM已设置，界面显示“开窗/关窗启动PWM已确认（完成/停止状态未知）”；不表示动作已完成、自动停止成功或机械窗户到位。超时显示“结果未知”。断开清除待发及待确认动作，重连不补发，不自动重试，迟到ACK仅保留日志。遥测与风机原有显示/数据入库保持。
- 运行更新后的Python源码或`智能通风系统_分页版.exe`，历史EXE不用于本轮四路控制。四路控制要求三块板配套支持编号1..4，由用户手动烧录默认业务HEX。MAX4466采集本轮尚未实现，停用旧SPH0645后声音显示无效值。

## 当前双声学显示约定（优先于下方历史阶段说明）

- 以 `../PROTOCOL_V4.md` 为准，兼容旧18字节并接收26字节扩展帧。保留六项BME及四路风机，声音1（左/SEL接地）、声音2（右/SEL接3V3）直接显示从机最新一个完整约63.7 ms短窗的去直流RMS整数；不取1秒最大值、不在界面保留峰值。单位PCM计数，不是dB，不做曲线。
- 合法零值显示0，无效显示--。仅匹配当前查询流水号的遥测更新显示、入库和更新时间；迟到帧只保留日志，断开及5秒超时清空。
- 数据库复用现有sound_rms_1/sound_rms_2整数列，不迁移结构、不增加依赖。旧双BME帧声音显示--，不将气压字节误读为声音。

## 主从双 BME280 联调约定

- 主机BME PB10/PB11软件I²C保持不变；从机BME PB6=SCL、PB7=SDA，I2C1硬件100 kHz。BH1750删除、DHT11停用，灯带保持既有PB13常亮逻辑，风机为PB1/PB8/PA1/PB9。
- BME 布局保持不变：flags bit0=首组为主机 BME、bit1=双 BME 布局、bit2=本轮从机通信在线；bit3=声学扩展。偏移 1–8 为主机温度 int16×10、湿度 uint16×10、绝对气压 uint32 Pa，9–16 为从机同三项；26字节偏移17为主机雨滴0/1/FF，旧18字节双BME仍为保留FF。多字节小端，无效值 0x8000/0xFFFF/0xFFFFFFFF。在线不等于 BME 正常，传感器故障仍可收到从机占位应答。
- 界面显示主从各三项、从机链路及左右声学整数，无效值为 `--`，保留四路风机。新版 flags=0x0B/0x0F，26 字节载荷、39 字节整帧；旧版 flags=3/7，18 字节载荷、31 字节整帧。v4 和 CRC 算法不变，CRC 位置随长度变化。旧 flags=0 保持历史布局，flags=1 保持单主机 BME 解释；其他长度/布局拒收。
- 串口连接后每秒请求缓存，已有遥测请求或风机 ACK 待确认时暂停自动轮询；遥测等待最长 5 秒。断开连接停止请求并清除当前显示，重连不自动启动风机。“读取单帧”请求一次新测量。
- 数据库结构和历史记录不改。原 `slave_temperature_c/slave_humidity_pct/slave_pressure_pa` 列继续存储偏移 1–8，结合 flags 判断来源（0=旧从机，1/3/7/0x0B/0x0F=主机）；旧双 BME 的声学/雨滴/DHT 列存 NULL，新帧两路声音复用 `sound_rms_1/sound_rms_2` 整数列，主机雨滴复用`rain_state`整数列0/1/NULL，DHT仍NULL。从机三项完整保留在 raw_frame 中，回读须按 flags 和长度解码；旧18字节雨滴沿用历史语义。这不是数据库迁移。
- 主机、从机、控制室与上位机须配套更新；控制室保持透传及关闭自身自动轮询，但必须烧入支持 26 字节的新版。硬件验证须在用户烧入三份最新 HEX 后完成。
- 当前双声学为最新完整短窗RMS，不上传原始音频、不绘制曲线、不做分贝换算或报警；主机单路雨滴仅检测上传。旧18字节帧一律不在本轮声学区域或主机雨滴面板显示数值。数据库列和历史记录保持不变；此前的1秒最大值与当前最新窗不是同一种统计，不能把旧记录重新解释为最新窗，帧内也没有算法版本标识。

## 风扇控制约定

- 滑块显示整数百分比，松开鼠标或释放调节按键后发送；数字框可输入 0–100，再点“发送”。不在拖动过程中连续发送，避免占用 LoRa 链路。
- 每路显示待发送、等待确认、已确认或超时；仅收到匹配流水号的成功 ACK 才视为主机已执行。ACK 不代表风扇实际转速测量。
- 输入为空、非数字、非有限值或超出 0–100 时拒绝发送；未连接时不保存待发送指令，重连不会自动启动风扇。
- 风扇编号和 GPIO 标签必须与主机 `fan_pwm.c` 一致；本次硬件驱动接法确认前不远程启动风扇。
- 四路风机：1/PB1、2/PB8、3/PA1、4/PB9；保留原1/2编号，新增3/4滑块、输入、发送按钮及独立状态。React、Python后端、演示与Tkinter回退均开放1..4，非法编号拒收；四路沿用原风机2的发送/ACK规则。外接MOS管，主机25 kHz高有效PWM，占空比是PWM高电平比例，不是实测RPM。主机启动默认0%，界面加载、重连不自动发送。
- 须配套更新主机固件并重启此上位机；协议版本与帧格式仍为 v4。早期四路版本的 GPIO 顺序与本版本不同，不使用旧界面混测。

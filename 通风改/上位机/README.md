# 上位机

## 界面与预览约定

- 新桌面界面使用 React/TypeScript、Vite 与 shadcn/ui 风格组件，Python 通过 pywebview 的 EdgeChromium/WebView2 窗口加载本地构建资源；实际运行无需 Node.js 或网络。保留 `legacy_tk.py` 作为 Tkinter 回退入口。
- 保留按钮禁用规则、滑块释放发送、串口通信、ACK/超时处理和数据库行为。完整保留声学单位、采样窗及窗户 PWM/ACK 说明，不增加远端功能、曲线、报警或数据库字段。
- 默认窗口 1120×800，按屏幕可用尺寸限制，最小 880×640；中部宽度不足时切换单列，内容过高时滚动，说明和状态随区域宽度换行，适配 Windows 字体缩放。
- `tests/` 可包含隔离界面验证：禁止打开真实串口，使用内存数据库或跳过数据库初始化；普通协议测试不要求可用显示环境。
- `build/ui-preview/` 仅存放可重新生成的界面预览脚本和截图，截图按尺寸/缩放命名，不提交；需要清理时由用户确认后删除。预览不得写入实际 `sensor_data.db` 或发送硬件指令。
- 本轮交付可直接使用的正式桌面 EXE、源码与运行说明。新增运行/打包依赖只安装在本目录 `.venv/`，使用 Python 3.13 64 位，不修改全局环境。
- Python 控制线程独占连接、发送、状态机和数据库；串口读线程只解析并入队。网页桥接只提交命令或读取快照。连接代次隔离旧读线程事件，关闭窗口时清空待发动作并关闭数据库。
- 浏览器预览与 `--demo` 桌面预览只能使用模拟串口及内存数据库；必须明确显示演示标识。界面加载不会自动连接设备或启动风机。前端输入草稿不由每 100 ms 的快照覆盖。
- 正式桌面枚举真实串口；端口输入保留手填，并提供展示全部检测端口的明确下拉按钮，不能按当前已填的端口过滤其他候选。普通浏览器页面不自动模拟设备，缺少桌面桥接时提示打开正式 EXE；隔离演示仅可通过明确的开发预览参数启用。
- 正式 EXE 使用真实串口后端，初始未连接，用户选择端口并连接后按原规则查询和保存遥测。前端与 Python 运行时随包离线分发，无需另装 Python、Node.js 或运行本地开发服务器；Windows 仍需已安装 WebView2 Runtime。
- EXE 的 `sensor_data.db` 放在 EXE 所在目录，复用已有文件与表结构；源码运行仍沿用当前工作目录。只改变打包程序的路径解析，不迁移、不复制或删除历史数据。
- `build/packaging/` 存放可重新生成的打包工作文件与隔离验证报告；正式产物为本目录 `智能通风系统_正式版.exe`。构建不得清理旧文件或覆盖历史 EXE，打包验证仅使用内存数据库与模拟串口；真实端口仅枚举，不打开。

## 当前单只 SG90 360°连续旋转窗口测试约定

- 遵循 `../PROTOCOL_V4.md` 的新 `SET_WINDOW=0x11`，载荷 `[1,0/1]`。界面增加“打开窗户”“关闭窗户”及状态；只控制从机PB8，不新增其他舵机、角度输入、数据库字段或依赖。
- 未连接时禁用按钮；前序遥测/风机未结束时只暂存一次窗口动作，并暂停新增遥测/风机发送。窗口待发或待确认期间禁用两个按钮；从实际串口发送起等待8秒，只匹配原流水号、命令11及合法状态0–3的ACK。
- 实物为360°连续旋转型，不做角度定位；开窗1700 us、关窗1300 us各运行300 ms，然后从机设置1500 us停止脉宽。1500 us需先空载校准，不能假定实际已经停止。
- 成功ACK只确认动作启动PWM已设置，界面显示“开窗/关窗启动PWM已确认（完成/停止状态未知）”；不表示动作已完成、自动停止成功或机械窗户到位。超时显示“结果未知”。断开清除待发及待确认动作，重连不补发，不自动重试，迟到ACK仅保留日志。遥测与风机原有显示/数据入库保持。
- 运行更新后的Python源码，旧EXE不在本轮重打包。三块板须支持现有0x11窗口协议；已配套更新的主机/控制室本次无需重烧，只更新从机timed300ms业务HEX，由用户烧录。

## 当前双声学显示约定（优先于下方历史阶段说明）

- 以 `../PROTOCOL_V4.md` 为准，兼容旧18字节并接收26字节扩展帧。保留六项BME及两路风机，声音1（左/SEL接地）、声音2（右/SEL接3V3）直接显示从机最新一个完整约63.7 ms短窗的去直流RMS整数；不取1秒最大值、不在界面保留峰值。单位PCM计数，不是dB，不做曲线。
- 合法零值显示0，无效显示--。仅匹配当前查询流水号的遥测更新显示、入库和更新时间；迟到帧只保留日志，断开及5秒超时清空。
- 数据库复用现有sound_rms_1/sound_rms_2整数列，不迁移结构、不增加依赖。旧双BME帧声音显示--，不将气压字节误读为声音。
- 首次从旧18字节布局升级到26字节双声学时，三块板须配套更新HEX，控制室旧固件拒绝26字节；运行更新后的main.py，旧打包EXE不用于本轮验收。由用户手动烧录，不自动起转风机。
- 本次统计方式切换只需用户烧录从机正常工程的默认业务HEX并重启更新后的Python源码；已支持26字节和窗口控制的主机/控制室无需重烧。保持约每秒查询一次，不将63.7 ms采样窗标为远端刷新速度。

当前可用的智能通风系统上位机统一放在此目录。

当前版本使用 LoRa 应用协议 v4：固定单组、26 字节单遥测帧（兼容旧 18 字节）、两路风机占空比控制。无效占位值统一显示为 `--`，数据写入现有 `telemetry_v4` 表，不改变其结构或历史记录。

## 主从双 BME280 联调约定

- 主机BME PB10/PB11软件I²C保持不变；从机BME PB6=SCL、PB7=SDA，I2C1硬件100 kHz。BH1750删除、DHT11停用，灯带保持既有PB13常亮逻辑，风机仍PB1/PB8。
- BME 布局保持不变：flags bit0=首组为主机 BME、bit1=双 BME 布局、bit2=本轮从机通信在线；新增 bit3=声学扩展。偏移 1–8 为主机温度 int16×10、湿度 uint16×10、绝对气压 uint32 Pa，9–16 为从机同三项，17=0xFF。多字节小端，无效值 0x8000/0xFFFF/0xFFFFFFFF。在线不等于 BME 正常，传感器故障仍可收到从机占位应答。
- 界面显示主从各三项、从机链路及左右声学整数，无效值为 `--`，保留两路风机。新版 flags=0x0B/0x0F，26 字节载荷、39 字节整帧；旧版 flags=3/7，18 字节载荷、31 字节整帧。v4 和 CRC 算法不变，CRC 位置随长度变化。旧 flags=0 保持历史布局，flags=1 保持单主机 BME 解释；其他长度/布局拒收。
- 串口连接后每秒请求缓存，已有遥测请求或风机 ACK 待确认时暂停自动轮询；遥测等待最长 5 秒。断开连接停止请求并清除当前显示，重连不自动启动风机。“读取单帧”请求一次新测量。
- 数据库结构和历史记录不改。原 `slave_temperature_c/slave_humidity_pct/slave_pressure_pa` 列继续存储偏移 1–8，结合 flags 判断来源（0=旧从机，1/3/7/0x0B/0x0F=主机）；旧双 BME 的声学/雨滴/DHT 列存 NULL，新帧两路声音复用 `sound_rms_1/sound_rms_2` 整数列，雨滴/DHT 仍 NULL。从机三项完整保留在 raw_frame 中，回读须按 flags 和长度解码。这不是数据库迁移。
- 主机、从机、控制室与上位机须配套更新；控制室保持透传及关闭自身自动轮询，但必须烧入支持 26 字节的新版。硬件验证须在用户烧入三份最新 HEX 后完成。
- 当前双声学为最新完整短窗RMS，不上传原始音频、不绘制曲线、不做分贝换算或报警，雨滴仍未实现。旧18字节帧一律不在本轮声学区域显示数值。数据库列和历史记录保持不变；此前的1秒最大值与当前最新窗不是同一种统计，不能把旧记录重新解释为最新窗，帧内也没有算法版本标识。

## 目录约定

- `main.py`：新桌面启动入口；`legacy_tk.py`：完整保留的 Tkinter 入口。
- `run_desktop.cmd`：使用本地环境的双击启动器，工作目录固定为本目录；附加 `--demo` 可启动隔离演示。
- `backend/`：协议、原数据库写入、独立控制器、桥接服务及模拟串口；不包含图形控件，不改变协议或 SQL 表结构。
- `frontend/`：React 界面、组件、样式与前端测试；构建输出放在 `frontend/build/`，依赖放在 `frontend/node_modules/`，均不提交。
- `requirements.txt`：桌面运行依赖；`THIRD_PARTY_NOTICES.md`：使用的开源组件及许可证。
- `requirements-build.txt`、`desktop.spec`、`build_exe.ps1`：固定本地打包工具、打包资源配置与可重复构建入口。
- `desktop_check.py`：显式启用的隔离打包验收，实际端口只枚举，采样验证使用进程内协议模拟与内存数据库，不改变正式默认模式。
- `tests/`：Python 协议、旧界面及新控制器隔离测试，不放 STM32 固件测试。
- `build/`：可重新生成的预览、截图及打包验证材料；不得包含生产数据库或真实设备录音，不自动删除。
- `智能通风系统.exe`：历史打包文件；不以旧 EXE 验收新界面。
- `智能通风系统_正式版.exe`：当前新桌面正式入口，双击后选择真实端口连接使用。

## 风扇控制约定

- 滑块显示整数百分比，松开鼠标或释放调节按键后发送；数字框可输入 0–100，再点“发送”。不在拖动过程中连续发送，避免占用 LoRa 链路。
- 每路显示待发送、等待确认、已确认或超时；仅收到匹配流水号的成功 ACK 才视为主机已执行。ACK 不代表风扇实际转速测量。
- 输入为空、非数字、非有限值或超出 0–100 时拒绝发送；未连接时不保存待发送指令，重连不会自动启动风扇。
- 风扇编号和 GPIO 标签必须与主机 `fan_pwm.c` 一致；本次硬件驱动接法确认前不远程启动风扇。
- 仅保留风机1/PB1、风机2/PB8，通道号仍为1和2；风机3/PA1、风机4/PB9暂时停用，移除滑块并拒绝发送通道3/4指令。外接 MOS 管，占空比是 PWM 高电平比例，不是实测 RPM。主机启动默认 0%。
- 须配套更新主机固件并重启此上位机；协议版本与帧格式仍为 v4。早期四路版本的 GPIO 顺序与本版本不同，不使用旧界面混测。

## 运行与验证

正式使用：双击本目录 **`智能通风系统_正式版.exe`**，点击串口输入框右侧下拉按钮，选择 `COM32`（或实际控制室端口），点击“连接设备”。连接后约每秒查询一次，收到的有效遥测显示在界面并写入 EXE 同目录的 `sensor_data.db`；也可点击“读取单帧”。不需要运行浏览器预览、Python 或 npm 命令。未点击连接时不会打开串口。

以下命令仅供源码开发与重建 EXE。在本目录初始化一次本地环境与离线界面：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
```

运行新桌面界面：

```powershell
.\.venv\Scripts\python.exe main.py
```

环境与界面资源准备后，可双击 `run_desktop.cmd` 打开程序。

必须使用 Windows 已安装的 WebView2 Runtime；桌面启动检查 EdgeChromium，不降级至旧网页引擎。本机已具备运行条件。源码继续使用工作目录原有 `sensor_data.db`，正式 EXE 使用 EXE 同目录文件，不移动或迁移历史数据库。串口参数仍为 115200，界面打开后须手动连接。

无硬件演示、资源检查及旧界面回退：

```powershell
.\.venv\Scripts\python.exe main.py --demo
.\.venv\Scripts\python.exe main.py --check
python legacy_tk.py
```

Tkinter 回退须使用带 Tkinter 的原 Python 环境。本机 Python 3.13 安装不带 Tkinter，现有默认 Python 3.14 可运行旧界面与原测试；若 Python 包含 Tkinter，也可运行 `main.py --legacy`。新桌面运行不依赖 Tkinter。

`--demo` 是显式开发验收选项，不枚举真实串口，只提供模拟端口，使用内存数据库。普通浏览器页面不模拟设备，提示使用正式 EXE；仅 `?preview=1` 启用隔离开发预览，模拟数据不能用于硬件验收。`--check` 不启动业务线程、不创建数据库、不打开串口。正式 EXE 无参数启动时始终使用真实串口后端。

验证：

```powershell
# 仓库根目录
python -m unittest discover -s "通风改/上位机/tests"
# frontend 目录
npm test
npm run build
```

原 64 项协议/操作测试和 5 项 Tkinter 布局测试保持原断言，入口改为 `legacy_tk.py`；新控制器与桌面入口另外进行隔离验证。前端测试覆盖提交时机、草稿保持、按钮规则及日志。预览覆盖默认/最小尺寸与 125%/150% 缩放，材料放 `build/ui-preview/`。

正式打包先构建前端，将当前 `frontend/build/` 资源、Python 运行时和第三方许可一起打包；输出 `智能通风系统_正式版.exe`。保留历史 EXE，不公开发布。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\build_exe.ps1
```

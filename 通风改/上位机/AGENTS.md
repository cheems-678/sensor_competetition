# 上位机开发约定

- 2026-10-06两分钟窗口调整：当前手动及自动温湿度趋势均使用最近120秒有效数据（覆盖此前五分钟约定），满两分钟手动检查可完整判定；自动仍连续超限30秒触发、低于80%持续60秒恢复、超过10秒缺口重新积累。事件证据、AI提示、模拟解释、前端进度和演示一致使用120秒。在119/120秒边界及150秒自动触发处验收；独立打包智能通风系统_AI主动监测版_两分钟.exe，run_ai_trend.cmd改为此入口，历史EXE保留，不改密钥保存或数据库格式。

- 2026-10-06主动趋势监测：串口接受有效遥测后始终积累本次会话的温湿度窗口，自动预警默认关闭；monitor_trends桥接命令由控制线程冻结当前趋势报告，给出主/从机方向、变化速度、有效时长和是否超限，同一次点击后台请求AI解释，平稳时也可分析。满五分钟且趋势超限时生成trigger=manual事件，不要求自动检测的30秒确认，明确标注“手动检查发现”；重复检查复用同一活动事件，不表示已自动确认。缺失/不足/断线不能判断正常，无可用数据不请求API。自动开关变化不清空实测窗口，关闭只停止自动来源事件，手动事件继续按原恢复条件跟踪。报告仅内存，按会话、规则和厂家版本取消旧分析；测试仍只用模拟串口、虚拟时间、内存数据库和假HTTP。另存智能通风系统_AI主动监测版.exe与run_ai_trend.cmd，保留所有历史产物，沿用现有加密配置格式及目录，不迁移数据库。

- 接口版模拟验收入口：run_ai_api_demo.cmd只启动同目录智能通风系统_AI接口版.exe并传入--demo，不自动连接硬件、不读取正式加密配置或自动请求API；演示中需用户重新选择真实API并输入密钥后点击分析。此启动器与run_ai_api.cmd及原离线演示入口并存，不覆盖历史产物。

- 2026-10-06真实AI接入：沿用预警后台队列，通过backend/ai_client.py的HTTPS Chat Completions调用DeepSeek/Kimi/自定义兼容接口；用户点击分析或“测试API”才请求，不自动控制设备。后台校验JSON输出、处理超时/鉴权/额度/格式错误，不把失败替换成模拟成功。正常模式默认真实API，--demo默认本地模拟；用户显式切换真实API后可用模拟数据测试并明确标识。测试一律注入假HTTP传输、内存数据库和隔离配置存储，不使用真实密钥或外部API。
- 用户明确要求重启记住密钥：backend/ai_config.py用Windows当前用户DPAPI加密配置，运行文件位于%LOCALAPPDATA%/SensorVentilation/ai-config.dpapi；此目录仅放该加密文件及写入失败留下的已加密临时文件，无明文密钥/日志，不自动清理。先加密、再原子保存，读取失败不自动覆盖。仅软件使用者主动保存配置时写入，不修改.env、全局依赖或系统设置。每厂家独立密钥，接口地址变化必须重新输入；快照仅暴露has_key/remembered，不返回密钥。源码控制器/测试默认内存存储，正式桌面入口显式启用本机持久存储；--demo和冻结自测隔离存储。独立交付智能通风系统_AI接口版.exe，保留演示版与历史EXE。

- 桌面启动系统信息查询：backend/windows_platform.py仅对当前进程的CPython WMI元数据查询设置2秒上限，超时后使用CPython原有Windows信息回退；执行宿主缺少PROCESSOR变量时通过IsWow64Process2只读获取架构。main.py在初始化WebView2前安装该适配，构建脚本复用同一模块。不改系统服务、全局Python、环境配置文件；构建生成的sitecustomize排除出产品包。需验证查询超时、原异常保留及冻结WebView2实际启动。
- 冻结启动顺序：backend/windows_platform_hook.py作为AI预警版PyInstaller首个运行时hook，在setuptools等第三方运行时hook之前安装上述适配；源码入口仍由main.py安装。包内验收核对hook先后顺序及sitecustomize未收集。

- 2026-10-06预警第一版：backend/warning_engine.py负责温湿度五分钟趋势与事件状态，warning_service.py仅在独立线程生成模拟解释，通过队列返回控制线程；warning_replay.py只读回放历史或合成数据。控制线程独占预警状态，按已接受遥测的sample_id/单调时间检测，实测默认关闭，测试参数0.4℃/min与1百分点/min；确认30s、恢复低于80%持续60s、超过10s数据缺口重积累。主动断开不报故障，应答超时提示通信异常。新增智能预警页、总览计数及折叠厂家配置（DeepSeek/Kimi/自定义兼容接口，各自保留内存草稿）；API Key禁用，不调用外网、不自动控制。事件最多200条且仅内存；模拟解释明确标识并按会话/配置版本丢弃旧结果。不修改数据库结构或.env。演示场景与回放使用虚拟时间，不连接硬件。验证材料沿用build/ui-preview/和build/packaging/，独立打包智能通风系统_AI预警演示版.exe，不覆盖历史EXE；不自动清理材料。

- 粮面测距图示（2026-10-06）：在现有ultrasonic-monitor组件内用本地SVG绘制粮仓剖面、仓顶传感器、水平粮面及垂直虚线，距离旁准确标注“到粮面表面的距离”与cm读数。剖面为固定示意、不是按实际仓高推算粮位；实际数值沿用滤波距离，失效显示--且虚线变灰。保留原始距离/脉宽/年龄与状态，协议/固件/后端不改。沿既有styles.css和组件测试验证桌面、窄窗口，另存智能通风系统_粮面测距图示版_20261006.exe，保留上一版。

- 2026-10-06粮面测距：按PROTOCOL_V4.md接受42字节扩展并兼容18/26/34，新增独立第九页“粮面测距”（置于声学页前），显示滤波/原始距离cm一位小数、脉宽us、已知年龄ms及有效状态；新增telemetry.ultrasonic快照，断线/超时/过期/旧帧清空。只呈现距离，三维模型不变；React/演示/Tkinter回退同步，不迁移数据库。沿用已有目录与本地依赖，独立打包智能通风系统_粮面测距版_20261006.exe，保留历史产物；冻结验证只用模拟串口和内存数据库。

- 遵循根目录 AGENTS.md 与本目录 README.md；先更新界面或目录约定，再实施调整。
- 风机控制固定四路：1=PB1、2=PB8、3=PA1、4=PB9；React、Python后端、演示与Tkinter回退使用同一映射及独立状态，沿用风机2的发送/确认规则，上电默认0%，不自动启动设备。
- main.py 仅负责桌面启动、资源路径和关闭处理；legacy_tk.py 保留已完成的 Tkinter 实现作为回退与原测试基线。
- backend/ 使用纯 Python，控制线程独占业务状态、串口发送和数据库写入；桥接线程只能入队或读快照。协议与数据库语义必须与 legacy_tk.py 一致。
- frontend/ 使用 React/TypeScript，组件放 src/components/，桥接与数据类型放 src/lib/，测试放 src/ 对应模块旁；构建输出为 build/，不引入远程字体或 CDN。
- 默认界面只呈现标题、图形、读数、单位、状态及操作；删除页介绍、重复副说明与协议页脚。模型只保留一个“模拟温度”标识，烟雾保留“相对指数/未标定”。必要的模型操作、传感器口径、风机规则和完整窗户PWM/ACK说明放对应功能区原生details/summary“说明”中，默认关闭，切页保留展开，重新启动关闭；未知、超时及错误仍直接显示。展开说明不发送设备指令。文案精简版独立打包，不覆盖历史EXE。
- 环境页不再放雨滴卡片，保留总览及独立雨滴页。在双BME读数下用本地SVG显示主/从机趋势，默认温度，可切换湿度/气压；单位°C/%/Pa，线性连点，不平滑或填补无效值。本次连接前端内存保留最近10分钟、最多1200个观测点，切页继续记录，重连或换端口清空，断线暂停并保留最后曲线且显示已断开。无效数据/超时插入断点，不把--当0。快照新增telemetry.sample_id（Controller生命周期内单调递增，仅接受匹配遥测时更新），不使用通用revision或秒级更新时间判断新测量；不改变设备协议、SQL结构、查询频率或自动控制。趋势版独立打包为智能通风系统_环境曲线版.exe，保留历史文件。
- 界面按粮仓总览、环境监测、雨滴监测、烟雾监测、声学监测、风机控制、窗户控制、通信日志八页组织，顶部串口栏与侧边导航共用。切页只改变可见区域，不重建桥接、连接或输入组件；隐藏的模型显式停止绘制，返回保留视角与模拟暂停状态。窄窗口导航横向排列，所有页面支持滚动与字号缩放；不引入仿真平台协议或其未实现功能。
- MQ-2按PROTOCOL_V4.md追加34字节遥测，兼容18/26字节；显示ADC原始值、PA7/AO电压及已知采样年龄。按用户现场观察暂定PA7参考点350/850/1500/2500 mV对应相对烟雾指数0/25/60/100，分段线性插值并限幅，明确标注经验参考、浓度未标定；指数不是百分比、ppm或消防报警判据。故障、采样年龄>=2000 ms、断线、离线或旧帧不计算指数并显示不可用，不自动学习或更新基线。独立烟雾页使用本地SVG/CSS烟雾动画，密度、透明度及颜色随指数变化；支持暂停、页面隐藏/离开视口停止运动、减少动态效果默认暂停，暂停仍更新数据。协议与数据库不变，React、演示及Tkinter回退数值语义一致；Tkinter保留原有布局。
- 总览标题右侧的天气标识与独立雨滴页共用主机实测状态：已连接且来源master的0=无雨太阳、1=有雨雨云，其余=灰色未知。本地SVG/CSS动画不表示雨量，支持暂停；页面隐藏、切页或离开可见区域时停止运动，减少动态效果偏好默认暂停。状态更新不受暂停影响，不发送设备指令、不修改协议或数据库。
- UI 呈现已有遥测、风机、窗口、串口与日志功能，以及独立的粮仓三维示意模型。整页使用深蓝黑科技配色。用户授权模型展示动态模拟温度：下冷上暖、配摄氏温度色谱、始终标明模拟，可暂停，不绑定遥测、不发送设备指令、不写数据库；环境面板仍仅显示串口实测值，不展示声学层析或机械位置。输入草稿保留到用户操作，滑块只在鼠标/触摸或调节键释放后发送；ACK 不表示机械动作完成。
- tests/ 与 frontend/ 测试只能使用模拟串口、内存数据库。预览截图放 build/ui-preview/；禁止自动连接硬件或创建生产数据库。
- 依赖使用本目录 .venv/ 与 frontend/node_modules/，提交 Python 依赖版本与 npm 锁文件，不修改全局工具或系统设置。
- 验证：仓库根目录运行 python -m unittest discover -s "通风改/上位机/tests"；frontend/ 运行 npm test 与 npm run build。桌面演示仅以 --demo 启动。
- 不删除现有文件或清理构建目录，不覆盖其他工程未提交改动；需要删除时先取得用户授权。

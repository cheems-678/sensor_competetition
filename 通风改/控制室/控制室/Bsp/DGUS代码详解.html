DGUS 串口屏代码详解

项目：LoraMaster V1.1（STM32F103 + FreeRTOS） | 涉及文件：Bsp/DGUS.c、Bsp/DGUS.h、Core/Src/usart.c、Core/Src/freertos.c

一、这块屏是什么，协议长什么样

DGUS 是迪文（DWIN）串口屏的图形开发体系。屏幕内部有一块 变量存储空间（VP 地址，0x0000–0xFFFF），界面上的每个控件（数据显示框、按钮、图标）都绑定一个 VP 地址。MCU 与屏幕只通过一条串口交换两种帧：

方向命令字含义
MCU → 屏0x82写变量空间（刷新显示、设置状态）
屏 → MCU0x83读变量空间的应答，触摸数据自动上传也走这个命令字

帧格式统一为：

0x5A 0xA5 | 数据长度 | 命令字 | VP地址高 | VP地址低 | 数据高 | 数据低 | ...

本工程硬件连接：USART1（PA9/PA10，115200 8N1） 接串口屏。

二、代码结构总览

模块职责
usart.cUSART1 初始化、逐字节中断接收进 Rx1Buffer、Usart_SendString() 发送
DGUS.c接收完整性判断、0x82 写数据封装、0x83 触摸数据应答
DGUS.hVP 地址枚举（粮面温湿度、环境温湿度、风速）
freertos.cStartLoRaTask 里轮询触摸应答；StartDGUSTask 每 5s 刷新环境数据

三、接收链路：字节是怎么进缓冲区的

main.c 初始化时开启 USART1 单字节接收中断：

HAL_UART_Receive_IT(&huart1, &rx1_data, 1);   // uart1 接收中断——串口屏

每收到一个字节触发一次回调，存入 Rx1Buffer 并重新挂中断（usart.c:302）：

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if(huart->Instance == USART1)
  {
    Rx1Buffer[rx1_pointer++] = rx1_data;      // 存字节，指针+1
    HAL_UART_Receive_IT(&huart1, &rx1_data, 1); // 重新挂中断等下一个字节
  }
}

这是典型的「中断攒包 + 主循环解包」模型：中断只负责搬字节，协议解析放在任务里做。

四、逐函数详解 DGUS.c

4.1 DGUS_Clear() — 清空接收缓存

void DGUS_Clear(void)
{
  memset(Rx1Buffer, 0, sizeof(Rx1Buffer));
  rx1_pointer = 0;
}

把缓冲区和计数器清零。注意：每次发送 0x82 写帧前也会调用它（见 4.3），目的是丢弃屏幕回发的应答字节，避免干扰触摸解析。

4.2 DGUS_WaitRecive() — 判断一帧是否收完

_Bool DGUS_WaitRecive(void)
{
  if(rx1_pointer == 0)               return REV_WAIT;   // 一个字节都没收到
  if(rx1_pointer == DGUS_cntPre) {                      // 计数不再增长 → 认为收完
    HAL_Delay(5);                                       // 再确认 5ms
    if(rx1_pointer == DGUS_cntPre) {
      rx1_pointer = 0;               return REV_OK;
    }
  }
  DGUS_cntPre = rx1_pointer;         return REV_WAIT;   // 还在收，记住当前计数
}

原理是空闲超时判帧：DGUS 协议本身有长度字节，但这里没有解析长度，而是用「两次轮询之间 rx1_pointer 不再变化」来判定一帧结束。串口帧间隔为 0 而帧与帧之间有空隙，所以这个方法可行，代价是每次都要多等一个轮询周期 + 5ms。

4.3 DGUS_WriteSingleData() — 写一个变量到屏幕

void DGUS_WriteSingleData(int S_Addr, int Data)
{
  char Com_all[16] = {0x5A, 0xA5, 0x05, 0x82,
                      S_Addr/256, S_Addr%256,   // VP 地址高/低字节
                      Data/256,   Data%256};    // 数据高/低字节
  DGUS_Clear();                                  // 清接收缓存
  Usart_SendString(huart1, (unsigned char *)Com_all, 8);
}

拼一条 8 字节的 0x82 写帧发出去。例如 DGUS_WriteSingleData(DGUS_GrainTemp, 253) 会把 25.3℃（屏端控件通常设置为 1 位小数，253 ÷ 10）显示到 0x3102 地址绑定的文本框上。

调用处在 StartDGUSTask（freertos.c:187），每 5 秒把 LoRa 收上来的粮面温度、环境温湿度、风速刷到屏上：

DGUS_WriteSingleData(DGUS_GrainTemp,  LoRaType.DS18B20_Data[0]);
DGUS_WriteSingleData(DGUS_EnvirHumi,  LoRaType.DHT11_Humi);
DGUS_WriteSingleData(DGUS_EnvirTemp,  LoRaType.DHT11_Temp);
DGUS_WriteSingleData(DGUS_GrainSpeed, LoRaType.WindPressure);
osDelay(5000);

4.4 DGUS_TouchAck() — 触摸数据应答（核心）

屏幕端按钮被按下时，会自动上传一条 0x83 帧：5A A5 06 83 VP高 VP低 00 01 ...（按键值写入）。本函数逐地址匹配 VP 并回写相应的变量组，让屏幕上的「选中态图标」跟着切换：

if((DGUS_WaitRecive()==REV_OK) & (Rx1Buffer[0]==0x5A) & (Rx1Buffer[1]==0xA5))
{
  if(Rx1Buffer[3]==0x83)                       // 是触摸/读应答帧
  {
    if((Rx1Buffer[4]==0x29) & (Rx1Buffer[5]==0x00)) {   // 降水模式按钮
      DGUS_Clear();
      char Com_all[20] = {0x5A,0xA5,0x09,0x82, 0x29,0x00,
                          0x00,0x01, 0x00,0x00, 0x00,0x00};
      Usart_SendString(huart1, (unsigned char *)Com_all, 13);
    }
    ... // 0x2901 降温模式、0x2902 储冷模式同理，各自把对应位置 1
  }
}

以「降水模式」为例：屏幕上传 VP=0x2900 值=1，MCU 回写一条 0x82 帧，把 0x2900=1、0x2901=0、0x2902=0 三个连续变量一次写入。屏幕上三个模式图标都绑定在变量图标控件上，于是「降水」点亮、另外两个熄灭 —— 实现了单选按钮组的效果。品种选择（0x2903–0x2908）是同一个套路。

现有代码的三处隐患，改触摸功能前建议先修：
  1. 逻辑与写成了位与：(a==b)&(c==d) 应写作 &&。当前能跑是因为两边恰好都是 0/1，但位与没有短路，属于埋雷写法。
  2. 层级错误：0x2906–0x2908 的三个分支（DGUS.c:114-131）写在了 if(Rx1Buffer[3]==0x83) 之外，任何帧头正确的包都可能误触发。应挪进 0x83 分支内。
  3. 缓冲区无溢出保护：Rx1Buffer[rx1_pointer++] 没有上限判断，异常数据流会越界写穿内存。

五、怎么加触摸功能（新增一个触摸按钮的完整流程）

触摸功能是「屏端配置 + MCU 端解析」两边配合，MCU 这边其实已经有完整框架，加一个按钮只要四步：

第 1 步：DGUS 开发软件里放控件

  1. 在 DGUS Tool（迪文屏开发软件）的页面上添加一个 「数据变量/增量调节」或「按键值返回」控件（按钮类用「按键值返回」，属性里勾选数据自动上传）。
  2. 给它分配一个 没用过的 VP 地址，比如 0x2910，设置按下时写入的值（比如 1）。
  3. 如果要显示选中态，再叠一个 变量图标控件，绑定同一个 VP 地址。
  4. 重新生成配置文件，下载进屏幕。

第 2 步：DGUS.h 里登记地址

建议把触摸 VP 单独建一个枚举，和显示地址分开：

typedef enum
{
    DGUS_TOUCH_MODE_JIANGSHUI = 0x2900,   // 降水模式
    DGUS_TOUCH_MODE_JIANGWEN  = 0x2901,   // 降温模式
    DGUS_TOUCH_MODE_CHULENG   = 0x2902,   // 储冷模式
    /* ... 已有的品种选择 ... */
    DGUS_TOUCH_FAN_SWITCH     = 0x2910,   // 新增：风机手动开关
} DGUSTouchAddrTypeNum;

第 3 步：DGUS_TouchAck() 里加解析分支

在 if(Rx1Buffer[3]==0x83) 内照现有套路加一个分支。触摸帧的数据在 Rx1Buffer[6]/[7]：

if((Rx1Buffer[4]==0x29) && (Rx1Buffer[5]==0x10))   // 风机手动开关
{
    uint16_t keyValue = ((uint16_t)Rx1Buffer[6] << 8) | Rx1Buffer[7];
    DGUS_Clear();

    if(keyValue == 1) {
        /* 在这里写按下后的动作，比如置位通风标志： */
        // SysVariType.vent_open_flag = 1;
    }

    /* 回写确认，让屏上的开关图标同步 */
    char ack[10] = {0x5A, 0xA5, 0x05, 0x82, 0x29, 0x10,
                    (char)(keyValue/256), (char)(keyValue%256)};
    Usart_SendString(huart1, (unsigned char *)ack, 8);
}

两点说明：

  • 读触摸值：按键值返回控件上传的值在数据区（第 7、8 字节），不是 VP 地址本身 —— 现有代码只按地址分支，是因为每个按钮占了独立 VP。如果多个按钮共用一个 VP（键值编码方式），就读 Rx1Buffer[6:7] 再 switch。
  • 回写确认：触摸上传后 MCU 用 0x82 把值写回同一 VP，屏端变量图标才会刷新。不写回的话图标可能不变化。

第 4 步：确认轮询位置

DGUS_TouchAck() 已在 StartLoRaTask 里被循环调用（freertos.c:174），新分支自动生效，不用动任务代码。但建议给这个任务加一个 osDelay(2)，当前是无延迟空转，空转时会挤占同优先级的 DGUSTask/ModBusTask 的调度时间。

进阶：页面切换与更多命令

需求帧
MCU 主动切页（如报警跳页）5A A5 07 82 00 84 5A 01 页号高 页号低（写系统变量接口 0x0084）
蜂鸣器提示音5A A5 05 82 00 02 时长高 时长低（写 0x0002，单位 10ms）
读屏上某个变量发 0x83 读帧，应答同样进 DGUS_TouchAck 的 0x83 分支，注意和触摸数据区分
总结：本工程的 DGUS 代码是「中断攒包 → 空闲判帧 → 按 VP 地址分支应答」的最小可用框架。新增触摸按钮 = 屏端配控件绑 VP → 枚举里登记地址 → DGUS_TouchAck 里加分支并回写确认。动手前建议顺手修掉第四节列的三处隐患。
